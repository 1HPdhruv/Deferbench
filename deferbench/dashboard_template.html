DeferBench

Evaluates security controls against delayed execution through trusted developer tools: an agent edits files after reading untrusted content, and a later, harmless-looking command (npm test, make, pytest, git commit) runs what was written. Every scenario is executed in a disposable workspace; a synthetic canary either reaches a 127.0.0.1 sink or it does not.

Known limitations

  • Agent actions are scripted replays, not live models; results say nothing about how often real agents take these actions.
  • Development scenarios were written by the defence author. Provisional and confirmatory sets are not human-independent; a human-independent holdout is pending.
  • Third-party tools ran hook-only with default policies (no OS sensors such as Gensee's Endpoint Security); their rows describe these configurations, not the full products.
  • ASK is not prevention if a reviewer clicks through — switch the resolution selector to approve-all.
  • Provenance attribution is unattainable for stateless controls by design; it measures traceability, not prevention.
  • Rates pool payload styles; n counts scenario × style, not independent attacks. One OS (macOS arm64).
