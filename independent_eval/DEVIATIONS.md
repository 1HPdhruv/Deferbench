# Deviations and exceptions
1. **No independent scenario set exists.** The requester asked the evaluator to write the unseen scenarios and to avoid inspecting the implementation. The evaluator in this session is the same assistant session that
   wrote the reference defence and the development/provisional scenarios; it has full exposure to `handoff.py`/the resolver, every development scenario, the provisional holdout expectations and all results. Strict separation
   is therefore impossible, and **no scenarios were authored here**: any set written by this session would be contaminated and would not satisfy §1.
2. What *was* done (2026-10-13, before any independent scenario existed): freeze record `FREEZE.json`; rubric defined before viewing any independent output (`rubric.json`); scorer and runner. The scorer was smoke-tested **only** on the
   existing non-independent provisional set; that output is not evidence for the independent question and is not stored here.
3. Because the scenarios are absent, none of the nine report questions (final-report §9) can be answered from independent data. Existing, non-independent evidence is in `results/final/` and `docs/NOVELTY_AUDIT.md`.
4. Freeze limitation: the project is not under version control, so the identifier is a source-tree SHA-256, not a commit.

## Update 2026-10-13 — evaluation performed (provisional, not human-independent)
5. **Author:** at the requester's choice, scenarios were authored by an isolated subagent instance (same model family) given only `author_kit/`. It was *instructed*, not technically prevented, from reading other files; its self-reported log (`holdout/AUTHOR_LOG.md`) lists only the kit files, JSON syntax checks, and the two permitted commands. The first run was cut off by a rate limit and resumed with the same instructions.
6. **Custodian contamination:** the custodian is the defence author's session. It read scenario names/commands and the author's report for size and duplicate checks (before running), and saw the *undefended* behaviour only through the author's repairs. It did not read defence outputs before the runs, and did not change the implementation (hash identical to the pre-set freeze).

Per protocol duplicates should be replaced; they were **not** replaced because replacement would have required a second author run and the overlap was only recognised from mechanism labels. This is reported as a limitation (Q4/Q6).
8. **Author-side baseline repairs:** I11 and I15 (nothing to commit; `README.md` write added). No expectation was changed to fit a result; the author saw only undefended outcomes.
9. **Seal status:** sealed *without* `--independent`; label remains `provisional-adversarial (NOT independent)`. The FREEZE.json scenario hash covers the 20 scenario files plus the author's log/notes/manifest/expected (24 files).
